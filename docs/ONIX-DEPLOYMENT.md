# Minecraft на ONIXPC

Целевая схема использует прежние Paper, Velocity и PostgreSQL в Docker Compose.
Миры и конфигурация находятся в ext4 внутри динамического диска
`M:\Services\agicraft-data-20261025.vhdx`. Его предел — 2 ТиБ; физический файл
растёт по мере записи. Операционные файлы находятся в
`M:\Services\agicraft-onix-ops`, служебные маркеры Windows — в
`M:\Services\agicraftmc`. Файлы с секретами не входят в Git.

WSL монтирует диск в `/mnt/wsl/agicraft-data`. Данные проекта доступны в
`/mnt/wsl/agicraft-data/agicraftmc`; Docker Desktop видит их через
`/run/desktop/mnt/host/wsl/agicraft-data/agicraftmc`. Файловая система Linux
сохраняет исходные UID, GID, режимы доступа, регистр имён и наносекундные метки.

Перед запуском проверяется UUID смонтированной файловой системы и внутренний
маркер завершённого развёртывания. Все рабочие bind-mount используют
`create_host_path: false`: отсутствие диска завершает запуск ошибкой, вместо
создания пустых каталогов для новых миров. Просмотр файлов через WSL:

```powershell
wsl -d Ubuntu-24.04 -u root -- ls -la /mnt/wsl/agicraft-data/agicraftmc
```

## Образы

Перенос со старого хранилища Docker в containerd требует регистрации каждого
образа с отдельной ссылкой. Сохраняются исходные конфигурационные blob и слои;
меняются только оболочка OCI и локальные теги. Перед запуском сравниваются
diff-ID всех слоёв и параметры конфигурации. Локальные ссылки
`agicraft-onix-source/<service>:20261024` используются с `pull_policy: never`.

## Сетевой вход

Docker Desktop скрывает исходный адрес входящего соединения. Нативный
`scripts/onix_game_proxy.py` принимает Java TCP на порту 25565 и передаёт его
на локальный порт 25566 с PROXY protocol v1. В Velocity включается
`haproxy-protocol`. Порт 25566 публикуется только на 127.0.0.1.

Для Bedrock мост принимает UDP на порту 19132, передаёт пакеты на локальный
порт 19133 с PROXY protocol v2. В Geyser включается соответствующая настройка
в секции `advanced.bedrock`; его Java-интеграция также учитывает режим Velocity.
Порт 19133 не публикуется на внешнем интерфейсе.

Входящий PROXY-заголовок принимается только от явно доверенного предыдущего
узла. Обычный клиент не может подставить себе чужой IP. Мост сохраняет отдельный
обратный UDP-канал для каждого клиента и удаляет неактивные каналы.

Временный мост на прежнем узле может использовать тот же скрипт для сохранения
доступа по старому IP во время обновления DNS. Обычные TCP-сервисы, например
закрытый канал БД, настраиваются без добавления PROXY-заголовков.

Пример конфигурации входного моста:

```json
{
  "trusted_proxy_ips": [],
  "tcp": [{"bind": ["0.0.0.0", 25565], "target": ["127.0.0.1", 25566], "proxy_protocol": 1}],
  "udp": [{"bind": ["0.0.0.0", 19132], "target": ["127.0.0.1", 19133], "proxy_protocol": 2}]
}
```

Запуск: `python scripts/onix_game_proxy.py <config.json>`. В рабочем контуре
используется фоновая задача Windows с явным путём к Python. Поле
`required_marker` запрещает запуск до завершения восстановления данных.

Проверка протокола и реального трафика на временных локальных портах:

```powershell
python -m unittest discover -s tests -p test_onix_game_proxy.py -v
```

## Данные и откат

Перед запуском проверяются размер и SHA-256 архива, затем контрольные суммы
восстановленных файлов. БД сохраняется логически и физически при остановленных
писателях. Для окончательного переключения нужен финальный снимок БД, если
веб-API продолжал работать во время переноса миров.

Старый игровой контур и его CI не должны одновременно запускать вторую
записываемую копию миров. Исходные данные сохраняются для отката. После приёма
новых игроков откат требует сначала сохранить новые изменения целевого узла;
запуск устаревшей копии без этого потеряет прогресс.

Проверка реальной перезагрузки хоста проводится отдельно: успешный запуск
фоновой задачи на работающем Docker не равен проверке холодной загрузки.

## Рабочий контур после переключения 25 октября 2026 года

Публичная A-запись `mc.agicraft.ru` направлена на ONIXPC. Домашний роутер не
обеспечивает WAN hairpin для самого узла, поэтому точечная запись hosts на
ONIXPC направляет этот домен на `192.168.1.10`. Docker Desktop также использует
это локальное разрешение. Публичный DNS при этом не меняется для других клиентов.

Вечером 25 октября сайт, backend и RCON web UI также перенесены на ONIXPC
в контур `M:\Services\agicraft-web-ops`. Локальный Caddy обслуживает сайты
напрямую. Сертификаты перенесены в постоянное хранилище; автоматическое
продление остаётся включённым. Прежние TCP-порты панели 4326 и 4327 ведут
на локальный RCON UI. Переходный edge на Linux сохраняет старый игровой IP.

Обратный SSH-туннель и relay-контейнеры первого этапа больше не используются:
backend и RCON UI подключаются через локальную Docker-сеть. Старый task
DBTunnel отключён и убран из startup-скрипта. Все исходные Docker-приложения
на jesbaserver остановлены, restart выключен; данные не удалены. До окончания
переключения DNS остаются только сетевые мосты. Подробности веб-этапа находятся
в `srv/agicraftweb/docs/onix-deployment.md` и отдельной резервной копии
`M:\Backups\jesbaserver-web\2026-10-25`.

PostgreSQL и volumes Filebrowser объявлены `external: true`, чтобы отсутствие
восстановленного volume останавливало запуск. Filebrowser слушает `0.0.0.0`
внутри своего контейнера, но публикуется только на `127.0.0.1:28090`.

Задача `Agicraft-ONIXPC-Startup` запускает скрытый PowerShell из
`M:\Services\agicraft-onix-ops\start.ps1`, проверяет UUID ext4, внутренний маркер,
обновляет только выделенные портовые отображения и запускает Compose с явным
контекстом `desktop-linux`. Стандартные потоки Compose сохраняются отдельно;
успех определяется кодом процесса, а не наличием вывода в stderr.

Общий mutex `Global\Agicraft-ONIXPC-DataMount` сериализует монтирование для
Minecraft и веб-старта. Если UUID уже соответствует, повторное монтирование
не выполняется. Одновременный запуск обеих задач проверен: result 0 у каждой.

Контрольные суммы, исходные restart policies, XML задач, финальный снимок БД и
порядок восстановления находятся в защищённом каталоге
`M:\Backups\jesbaserver-minecraft\2026-10-24`. В Git эти файлы не входят.
